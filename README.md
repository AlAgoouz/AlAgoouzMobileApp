# Agouz — بُن العجوز

تطبيق إدارة المخزون والإنتاج والمبيعات والحسابات. المستودع المعتمد: [AlAgoouzMobileApp](https://github.com/AlAgoouz/AlAgoouzMobileApp).

- المشروع على Vercel: `agouz` داخل `AlAgoouz`.
- قاعدة Supabase الجديدة: `Agouz` (`srinizbfqozvdqsuvvbc`).
- رابط المشروع: [Agouz](https://agouz.vercel.app).
- راجع [نتائج التحقق على GitHub Actions](https://github.com/AlAgoouz/AlAgoouzMobileApp/actions/workflows/verify.yml) و[ملاحظات الإصدار](RELEASE.md).

## أول استخدام

يبدأ المتجر فارغًا، دون أرصدة أو مبيعات تجريبية. إنشاء الحسابات وإسناد صلاحياتها يتمان عن طريق المالك فقط من إدارة Supabase؛ التسجيل العام مغلق. يدخل المستخدم بالبريد وكلمة المرور للحساب المجهز له، أو يستخدم استعادة كلمة المرور. يبدأ المالك الوحيد بحصة 100%.

لا تُحفظ كلمات مرور داخل بيانات الشركاء أو النسخ الاحتياطية. بيانات الاعتماد الخاصة لا تُنشر في المستودع، والواجهة تستخدم المفتاح العام مع حماية الصفوف.

### تشغيل الواجهة وواجهة Python على Windows

بعد ضبط `.env.local` بعنوان مشروع Supabase والمفتاح العام، جهّز بيئة Python مرة واحدة:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-local.txt
```

شغّل `OPEN_APP.bat`. ينتظر المشغّل جاهزية Python ثم يفتح Vite، الذي يوجّه طلبات `/api` إلى الخادم المحلي. استخدم Python من 3.12 إلى 3.14. قاعدة البيانات هي مشروع Supabase المحدد في الإعدادات.

لتوليد PDF على Windows، ثبّت Pango عبر MSYS2 واضبط `WEASYPRINT_DLL_DIRECTORIES` بمسار مجلد DLL، مثل `C:\msys64\ucrt64\bin`. [تعليمات WeasyPrint](https://doc.courtbouillon.org/weasyprint/stable/first_steps.html#windows)

تعمل الاختبارات ببيانات معزولة دون كتابة على قاعدة الإنتاج. `npm run build` يفحص TypeScript ويبني نسخة Vite.

انسخ `.env.example` إلى `.env.local` وحدد مشروع الاختبار الصحيح قبل `npm run dev`. تشغيل الواجهة محليًا لا يعني أن قاعدة بياناتها تجريبية؛ العنوان المضبوط هو الذي يحدد الوجهة.

## قاعدة مستقلة جديدة

طبّق `supabase/schema.sql` ثم ملفات الترقية في `supabase/migrations` بالترتيب. ملف `20261101001820_owner_bootstrap.sql` يتيح ربط أول مالك بعد تحقق بريده؛ يضبط المسؤول البريد المسموح داخل `bon_erp_private.owner_config` على الخادم فقط. لا تُعد منح المستخدمين كتابة مباشرة على جدولي المتجر والكاشير.

الحفظ يمر عبر `bon_erp_save_store`، والرفع عبر `bon_erp_enqueue_export`. إعداد أعضاء إضافيين يتم بصورة صريحة عبر نسخة خاصة من `supabase/member-mapping.example.json` وأداة `supabase/generate-member-setup.mjs` التي تولد SQL للمراجعة دون الاتصال بالخادم أو استبدال متجر موجود.

## الكاشير

المسار الحالي للتقارير المطبوعة UWS هو الرفع من الموقع؛ يُستخرج تاريخ العمل من داخل التقرير، وإيراد اليوم من Begun فقط. يظهر الإيراد والمتحصلات فور حفظ التقرير المالي. تقرير الأصناف يطابق كود الكاشير ويستخدم وزن البيع أو عدد الوحدات حسب الصنف. توزيع أوزان AlAgoouz ووزن إضافات Tahwiga غير موجودين في التقرير الحالي، فيتوقف اعتماد المخزون والتكلفة لحين استكمال تفاصيلهما، مع بقاء الإيراد ظاهرًا والربح غير مكتمل. رصيد البداية مستقل عن المبيعات ويظهر ضمن أموال النشاط. راجع [قواعد التشغيل](docs/BUSINESS_RULES_AR.md).

أداة المجلد القديمة تدعم الجداول العامة ولم تُعتمد لملفات UWS المطبوعة مباشرة. تحتاج حسابًا مخصصًا بعضوية `cashier`؛ حساب المالك الأول لا ينشئ هذا الحساب تلقائيًا. اضبط الإعدادات في `.env.local`، وضع تاريخ المبيعات `YYYY-MM-DD` في اسم الملف أو حدد `CASHIER_SALE_DATE` صراحةً، ثم `npm run watcher`.

لا يُؤرشف ملف قبل تأكيد الرفع، ولا يُعتمد ملف ناقص المطابقة جزئيًا. المرتجعات السالبة تُسجل من الفاتورة الأصلية، ولا تتحول إلى مبيعات موجبة.

## ضوابط التشغيل

- عرّف بيانات المنتج أولًا، ثم أضف مكونات التوليفة أو المشروب أو التحويجة من قسم «الوصفات». يظل التعريف تحت الاستكمال حتى اعتماد وصفته وتكلفتها؛ الإنتاج قسم مستقل للتوليفات فقط.
- الجملة والإنتاج يتطلبان رصيدًا كافيًا. تقرير يوم الكاشير يسمح برصيد سالب ويُظهر العجز، ولا يُكرر الإيراد أو التقرير لنفس اليوم. يمنع السداد الزائد.
- تُحفظ الفواتير والدفعات والمصروفات الملغاة مع أدلة العكس؛ لا تُحذف المستندات المعتمدة مباشرة.
- يُرفض إلغاء شراء إذا تغير مخزونه بعد اعتماده؛ يلزم تسوية الحركة اللاحقة أولًا.
- عند التعارض، احتفظ بنسخة من المسودة ثم أعد تحميل بيانات السحابة وراجع عمليتك. لا يوجد دمج تلقائي قد يمسح عمل جهاز آخر.
- استرجاع النسخة يُراجع قبل تطبيقه. الحد الحالي للملف 10 MB وسعة المسودة المحلية محدودة بسعة المتصفح.

### نطاق النسخ الاحتياطي للملفات

حساب النسخ المخصص لديه صلاحية قراءة مخازن Supabase وملفاتها حتى تشمل النسخة المشفرة المخازن الحالية وأي مخازن جديدة. يستخدم مسار الاستعادة المعزول هذه التغطية للتحقق من محتوى الملفات وملكيتها. تعرض لوحة التطبيق تفاصيل تشغيل النسخ لحساب المالك.
