# Agouz — بُن العجوز

تطبيق إدارة المخزون والإنتاج والمبيعات والحسابات. المستودع المعتمد: [AlAgoouzMobileApp](https://github.com/AlAgoouz/AlAgoouzMobileApp).

- المشروع على Vercel: `agouz` داخل `AlAgoouz`.
- قاعدة Supabase الجديدة: `Agouz` (`srinizbfqozvdqsuvvbc`).
- رابط المشروع: [Agouz](https://agouz.vercel.app).
- راجع [ملاحظات الإصدار](RELEASE.md) ونتائج الاختبارات داخل `audit` للتمييز بين ما اختُبر وما يحتاج جهازًا أو تأكيدًا من المالك.

## أول استخدام

يبدأ المتجر فارغًا، دون أرصدة أو مبيعات تجريبية. استخدم «إنشاء حساب المالك لأول مرة» بالبريد المعتمد، واختر كلمة المرور بنفسك ثم أكّد البريد. لا يمنح التسجيل ببريد آخر صلاحية للمحل. يبدأ المالك الوحيد بحصة 100%.

لا تُحفظ كلمات مرور داخل بيانات الشركاء أو النسخ الاحتياطية. بيانات الاعتماد الخاصة لا تُنشر في المستودع، والواجهة تستخدم المفتاح العام مع حماية الصفوف.

## التطوير والتحقق

استخدم Node.js 24 ثم:

```sh
npm ci
npm test
npm run build
```

تعمل الاختبارات ببيانات معزولة دون كتابة على قاعدة الإنتاج. `npm run build` يفحص TypeScript ويبني نسخة Vite.

انسخ `.env.example` إلى `.env.local` وحدد مشروع الاختبار الصحيح قبل `npm run dev`. تشغيل الواجهة محليًا لا يعني أن قاعدة بياناتها تجريبية؛ العنوان المضبوط هو الذي يحدد الوجهة.

## قاعدة مستقلة جديدة

طبّق `supabase/schema.sql` ثم ملفات الترقية في `supabase/migrations` بالترتيب. ملف `20261101001820_owner_bootstrap.sql` يتيح ربط أول مالك بعد تحقق بريده؛ يضبط المسؤول البريد المسموح داخل `bon_erp_private.owner_config` على الخادم فقط. لا تُعد منح المستخدمين كتابة مباشرة على جدولي المتجر والكاشير.

الحفظ يمر عبر `bon_erp_save_store`، والرفع عبر `bon_erp_enqueue_export`. إعداد أعضاء إضافيين يتم بصورة صريحة عبر نسخة خاصة من `supabase/member-mapping.example.json` وأداة `supabase/generate-member-setup.mjs` التي تولد SQL للمراجعة دون الاتصال بالخادم أو استبدال متجر موجود.

## تجربة متصفح معزولة

شغّل `node tests/support/local-server.mjs`، ثم في PowerShell منفصل:

```powershell
$env:VITE_SUPABASE_URL='http://127.0.0.1:5281'
$env:VITE_SUPABASE_PUBLISHABLE_KEY='local-disposable-public-test-key'
npm run dev -- --port 5280 --strictPort
```

افتح `http://127.0.0.1:5280`. المستخدمون `owner1@local.test` إلى `owner4@local.test` وكلمة المرور `Local-Test-Only-123!` تخص هذه التجربة فقط. تُمحى القاعدة المؤقتة عند إيقاف خادمها ولا تتصل بأي مشروع حقيقي. لا تحاكي هذه التجربة خدمة Realtime المستضافة؛ يعمل التحديث الدوري كبديل.

## الكاشير

تحتاج أداة المجلد حسابًا مخصصًا بعضوية `cashier`؛ حساب المالك الأول لا ينشئ هذا الحساب تلقائيًا. اضبط الإعدادات في `.env.local`، وضع تاريخ المبيعات `YYYY-MM-DD` في اسم الملف أو حدد `CASHIER_SALE_DATE` صراحةً، ثم `npm run watcher`.

لا يُؤرشف ملف قبل تأكيد الرفع، ولا يُعتمد ملف ناقص المطابقة جزئيًا. المرتجعات السالبة تُسجل من الفاتورة الأصلية، ولا تتحول إلى مبيعات موجبة.

## ضوابط التشغيل

- يمنع البيع عند نقص الصنف أو مكونات الوصفة، ويمنع السداد الزائد.
- تُحفظ الفواتير والدفعات والمصروفات الملغاة مع أدلة العكس؛ لا تُحذف المستندات المعتمدة مباشرة.
- يُرفض إلغاء شراء إذا تغير مخزونه بعد اعتماده؛ يلزم تسوية الحركة اللاحقة أولًا.
- عند التعارض، احتفظ بنسخة من المسودة ثم أعد تحميل بيانات السحابة وراجع عمليتك. لا يوجد دمج تلقائي قد يمسح عمل جهاز آخر.
- استرجاع النسخة يُراجع قبل تطبيقه. الحد الحالي للملف 10 MB وسعة المسودة المحلية محدودة بسعة المتصفح.
- ملفات التشخيص القديمة في `audit` أدلة للفحص الأول؛ مجموعة قبول النسخة الحالية هي `npm test`.
