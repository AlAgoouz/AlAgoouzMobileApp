# النسخ الاحتياطي والاسترجاع

وجهة النسخ هي مجلد Agouz Backups على Google Drive الخاص بالمالك. الملفات مشفرة بـAES-256-GCM؛ النسخة تشمل قاعدة PostgreSQL وبيانات Auth ومصدر التطبيق المحفوظ في Git، وتعريفات الأدوار دون كلمات مرورها.

التشغيل اليومي معرف في `.github/workflows/backup.yml` الساعة 6 صباحًا بتوقيت القاهرة على GitHub، ويستخدم حساب قاعدة مستقلًا للقراءة فقط. لا يعتمد التشغيل على جهاز المالك. يمكن تشغيله يدويًا من Actions باسم Agouz daily verified backup.

كل تشغيل يصدّر القاعدة، ويشفّرها، ويرفع ملفًا باسم مستقل، وينزّله مرة أخرى ويتحقق من بصمته. ثم يسترجعه في قاعدة معزولة، ويقارن كل جداول البيانات والتسلسلات، ويختبر تسجيل الدخول واستعادة كلمة المرور بحساب تجريبي داخل النسخة فقط. لا يُحدّث `latest-verified.json` إلا بعد نجاح الاختبارات وإزالة بيئة الاختبار وإعادة تنزيل الملف الموثّق من Drive. الفشل يحافظ على النسخة السابقة ويظهر كتشغيل فاشل في GitHub.

مفتاح التشفير محفوظ كسر مستقل في GitHub وفي المجلد الخاص على D. بيانات اتصال القاعدة وGoogle Drive محفوظة كأسرار GitHub؛ لا ترفع ملفاتها أو مفتاح التشفير إلى المستودع أو بجوار الأرشيف. يلزم المفتاح لفك النسخ القديمة حتى بعد تغيير إعدادات الاتصال.

لفحص الاسترجاع من Drive على جهاز مجهز، اضبط مسارات أدوات PostgreSQL وrclone وملف الاتصال ومجلد النسخ الخاص، وضع `recovery-key.base64` داخله، ثم شغّل `node scripts/backup/check-from-drive.mjs`. الأداة تنزّل آخر نسخة وتختبرها في قاعدة جديدة معزولة، ولا تستبدل الإنتاج. استبدال الإنتاج خطوة منفصلة تتطلب مراجعة النسخة المسترجعة وإعدادات Auth وRLS والروابط قبل تحويل التطبيق إليها.

صيغة النسخ الثانية تشمل أيضًا ملفات Storage العادية ببايتاتها الأصلية، وتعريفات الحاويات والملكية والبيانات الوصفية، وأسرار Vault بقيم محمولة يعاد تشفيرها بمفتاح وجهة الاسترجاع. تبقى هذه القيم وبيانات ربط النسخ داخل الأرشيف المشفر؛ مفتاح تشفير الأرشيف نفسه لا يدخل النسخة. لا يحذف النظام نسخ Drive القديمة تلقائيًا.

يقرأ حساب Auth مستقل ملفات Storage فقط، ولا يملك عضوية ERP أو صلاحية كتابة الملفات. دور القاعدة `agouz_backup` يملك منفذ تصدير Vault خاصًا للقراءة، دون منحه فك تشفير عام. تُقارن بيانات الملفات وVault قبل التصدير وبعده، ويُرفض الملف الناقص أو تغير المصدر أثناء القراءة. الاسترجاع يرفع الملفات إلى خدمة Storage معزولة ويعيد تنزيلها ويطابق بصماتها، ويختبر القيم المفكوكة للأسرار ومُعرّفاتها بعد إعادة تشفيرها.

رمز `Agouz Daily Recovery Settings` محصور في مشروع Agouz وبصلاحيات قراءة الإعدادات فقط، دون انتهاء تلقائي حسب اختيار المالك. تُنسخ إعدادات Auth والتخزين وRealtime وData API وPostgreSQL والاتصال وحماية الشبكة وSSL، ومصدر Edge Functions إن أضيفت. إعدادات Vercel ومتغيراته الحالية وإرشادات إعادة ربط Google Drive جهزت في السر `AGOUZ_RECOVERY_CONFIG_JSON`؛ يجب تحديث هذه الحزمة بعد تغيير إعدادات Vercel. لا تحفظ مفاتيح النسخ أو محتوى الحزمة في المستودع العام.

واجهة إدارة أسرار Edge Functions تعيد بصمات، وليست القيم الأصلية. لأي سر مخصص اسمه `NAME`، احفظ نسخة قيمته في Vault باسم `agouz.edge.NAME` بالتزامن مع تغييره؛ النسخ يطابق البصمتين ويتوقف إن غابت القيمة أو اختلفت. إن حجب مزود الخدمة قيمة إعداد، يستخدم الإيداع `agouz.provider.auth.FIELD` بدل ادعاء نسخ القيمة المخفية. مفاتيح Supabase المولدة وروابط قاعدة المشروع تُنشأ أو تُدوّر على وجهة الاسترجاع؛ لا يعاد استعمال اعتماد المشروع المصدر تلقائيًا.

النسخ منطقي ويستهدف بيانات التطبيق وملفات Storage العادية وVault والإعدادات المذكورة، وليس صورة لحسابات الشركات أو الفوترة. PostgreSQL large objects، وسجلات Storage المتقدمة غير المغطاة مثل الحاويات المتجهية والتحليلية وأجزاء الرفع غير المكتمل، توقف اكتمال النسخة عند وجود بيانات فيها. يلزم تجهيز تصديرها قبل تفعيلها. إنشاء حسابات الخدمات والدفع والصلاحيات الجديدة وتطبيق إعدادات الإنتاج على وجهة أخرى خطوات استرجاع منفصلة؛ اختبار الاسترجاع لا يغير إعدادات الخدمات الحية.

اتصال Drive يستخدم عميل Google OAuth خاصًا باسم Agouz Backup Runner ضمن تطبيق Agouz Backups وحساب المالك. وضع الاتصال In production؛ نجح تجديد التفويض فعليًا، ثم نجح التشغيل السحابي 41376376737 بالاتصال الخاص، مع استرجاع ومطابقة 51 جدولًا والتسلسلات واختبارات Auth. التطبيق للاستخدام الشخصي ولم يُقدَّم كتطبيق معتمد من Google للعامة. أي انتهاء تفويض لاحق يظهر كفشل في التشغيل ولا يغيّر آخر نسخة موثقة.

نظرًا لأن المستودع عام، يسجل تشغيل صيانة منفصل علامة شهرية دون بيانات المحل لتجنب تعطيل GitHub للجدولة بعد 60 يومًا من غياب نشاط المستودع. وظيفة النسخ نفسها تظل بصلاحية قراءة المستودع فقط؛ صلاحية الكتابة تخص وظيفة الصيانة. قد يتأخر موعد التشغيل تحت ضغط خدمة GitHub.
